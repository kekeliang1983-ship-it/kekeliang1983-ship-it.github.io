## 2. 本地开发

```bash
npm install          # 首次 / 依赖变更后
npm run dev          # 启动 dev 服务器 → http://localhost:5173/
```

- **管理后台**：`http://localhost:5173/#/admin`（仅在 `import.meta.env.DEV` 下注册路由 + 写接口生效）。
- **⚠️ 坑 1**：用 `npm run preview` 或生产链接进 `/#/admin` 会**打回游戏首页**——因为生产构建 `DEV=false`、后台路由不注册、`/__admin_api` 保存插件只挂 `vite dev`。改内容必须走 `npm run dev`。
- **启用后台口令（C）**：
  ```bash
  ADMIN_TOKEN=你的口令 npm run dev
  ```
  不设则不拦截（向后兼容）。口令存 sessionStorage，刷新需重输。真实口令勿写进会被提交的 `.env`（用 `.env.local`，已被 gitignore）。

## 3. 构建

```bash
npm run build        # 输出到 dist/（CI 同此命令）
```

- **⚠️ 坑 2（沙箱/权限环境）**：若构建静默失败（exit 1、无输出），多为 vite 清空已存在 `dist` 触发 safe-delete 拦截。规避：用全新目录输出。
  ```bash
  npx vite build --outDir dist-relN    # N 取未用过的新数字，如 dist-rel12
  ```
  本机正常环境直接用 `npm run build` 即可，无需此技巧。

## 4. 部署（GitHub Pages 自动）

仓库是 **GitHub Pages 根仓库**，Push 即自动部署，无需手动传文件。

### 4.1 自动部署流程
`git push`（main 分支）→ GitHub Actions 依次执行：
1. `npm ci`（按 lock 安装）
2. `node scripts/validate-content.mjs`（**D：校验 content/*.json 合法性，不过则部署中止**）
3. `npm run build`
4. `upload-pages-artifact(dist)` → `deploy-pages`

约 1 分钟完成，玩家刷新即得新版本。

### 4.2 本地推送
```powershell
cd "C:\Users\KEKELIANG\WorkBuddy\NEW OBB\CozyCreatures"
git push
```
> 本机若无 GitHub 凭据，push 前先 `gh auth login` 一次（浏览器登录）。

### 4.3 本机 HTTPS 被网络重置时
国内直连 `github.com` HTTPS 偶发 `Connection was reset`。两种解法：
- **CodeBuddy 环境**（已配 `gh` 登录态）：`gh auth setup-git` 配置 credential helper 后直接 `git push`。
- **本机配 SSH key**：`git remote set-url origin git@github.com:kekeliang1983-ship-it/kekeliang1983-ship-it.github.io.git` 再 `git push`。

### 4.4 ⚠️ 坑 3：`package-lock.json` 必须提交
改 `package.json`（如加依赖）后**务必把 `package-lock.json` 一起 `git add` 提交**，否则 CI `npm ci` 报 `Missing from lock file` / `EBADENGINE` 直接失败。

## 5. 内容热更新（零代码发布）

游戏所有可调数值都在 `public/content/*.json`（14 个模块）。更新内容无需改代码：

1. 本地 `npm run dev` 进 `#/admin` 后台改参数（或手动编辑 `public/content/*.json`）；
2. `git add public/content/xxx.json && git commit && git push`；
3. 自动重部署后，**玩家刷新页面即得新内容**——SW 已配置 `fetch` 守卫 `/content/*` 永远走网络、不进缓存。

> 后台改完点保存是写回本地 `public/content/*.json` 磁盘文件，仍需走「提交 + push」才会发布到线上。

## 6. 联机后端（Supabase 匿名表）

| 配置 | 位置 | 说明 |
|---|---|---|
| 项目 URL / anon key | `.env.production` / `.env.development` | 已提交（anon key 公开安全，可嵌前端） |
| 表结构 | Supabase SQL Editor 手动执行 | 见下「建表清单」 |
| 客户端 | `src/services/supabase.ts` | 未配置/出错/超时自动降级本地 |

**建表清单（需在 Supabase 控制台 → SQL Editor 执行，显示 Success 即生效）**：
- B2 漂流瓶：`public.drift_bottles` + RLS(anon insert/select) + `random_bottle()`
- B3 访友：`public.farm_snapshots` + `public.farm_visits` + RLS + `random_farm_snapshots(p_limit, p_exclude)`
- B4 竞速榜：`public.race_scores` + RLS(anon insert/select) + `best_race_opponents(p_track, p_exclude, p_limit)`

> 若重跑 SQL 报 `policy already exists`，用带 `drop policy if exists` 的覆盖版（见各阶段记录）。建表后可用 Node 脚本实测：上传→随机拉→清理。

## 9. 常见坑速查

| 现象 | 原因 | 解决 |
|---|---|---|
| 后台进不去 / 打回游戏 | 用了 preview 或生产链接 | 必须 `npm run dev` |
| CI `npm ci` 失败 | `package-lock.json` 没提交 | 改 package.json 后一起提交 lock |
| `git push` Connection was reset | 本机 HTTPS 被网络重置 | `gh auth setup-git` 后 push，或切 SSH |
| 构建静默 exit 1 无输出 | vite 清空旧 dist 被沙箱拦 | 用全新 `--outDir dist-relN` |
| 改了 SW 不生效 | 改错文件 | 改 `public/sw.js`，`src/sw.ts` 是占位壳不参与部署 |
| 玩家看不到新内容 | SW 缓存了旧 JSON | 已加 `/content/*` 守卫，硬刷 Ctrl+F5；确认已 push |

# 后台调参操作手册 · CozyCreatures

> 适用：想改游戏数值 / 文案 / 素材，但不想碰代码的人。
> 前置：已完成「部署指南 → 2. 本地开发」中 `npm run dev` 启动。

---

## 1. 后台是什么、能干嘛

后台是一个 **仅 dev 模式可用** 的可视化编辑器，直接改 `public/content/*.json`。
改完存盘 → 你（或协作者）`git commit && git push` → GitHub Pages 自动重部署 → **玩家刷新即得新内容**（SW 已配置不缓存 `/content/*`，无需清缓存）。

**核心原则：配置态（content JSON）与运行态（玩家 localStorage 进度）严格分离。**
后台改的是「工厂参数」，不影响已在线玩家的存档，只影响他们下一次读取时的默认值/新内容。

---

## 2. 如何打开后台

1. 终端启动开发服务器：
   ```bash
   npm run dev
   ```
2. 浏览器打开 Vite 提示的地址（默认 `http://localhost:5173`）。
3. 把地址栏路径改成 `#/admin` 并回车 → 例如 `http://localhost:5173/#/admin`。
4. 若你给后台设了口令（`ADMIN_TOKEN`，见「6. 鉴权」），会先弹出口令框，输入正确才进。

> ⚠️ 后台**只在 `npm run dev` 下存在**。`npm run preview` 和 `npm run build` 产物里没有后台路由，打不开是正常的。

## 3. 后台界面与操作

进入后是「左侧模块树 + 右侧编辑器 + 顶部操作条」。

### 顶部操作条
- **保存**：把当前编辑器内容写回 `public/content/<id>.json`。保存前会过一次**结构校验**（D 质量防护），JSON 非法会被拦下并提示。
- **快照**：给当前模块存一份快照（可命名），用于回滚。
- **对比/变更**：打开「变更对比」弹窗，看到「打开时内容 ↔ 当前内容」的 diff，确认无误再保存。
- **回滚**：从快照列表选一份恢复。
- **导入 / 导出**：把某模块 JSON 整份导出为文件，或导入一份覆盖（适合跨环境迁移配置）。

### 左侧模块树（按分组）
分组与模块（共 12 项，全部已接入内容层 = 改完 App 实时生效）：

| 分组 | 模块 | 对应文件 | 改了影响什么 |
|---|---|---|---|
| 内容素材 | 画境·壁纸/白卡 | `gallery.json` | 壁纸库、隐藏白卡（图/属性/品质/价） |
| 内容素材 | 天籁·曲库 | `music.json` | 曲目、解锁条件、歌单/场景合集 |
| 内容素材 | 素材池 | `pool.json` | 头像库(emoji+五行+中文名)/起名词库/五行底环渐变 |
| 首页装扮 | 首页整体装扮 | `home.json` | 底图/今日心语/7 大版块白卡图标与背景 |
| 首页装扮 | 首页 Banner 文案 | `banner.json` | 顶部展示栏标题/按钮文案/背景图 |
| 玩法配置 | 仙宠 | `pet.json` | 仙宠全局参数/换皮/旅行档位/食物价/文案池 |
| 玩法配置 | 神龛 | `shrine.json` | 上香/神恩/签文/今日宜忌 |
| 玩法配置 | 法器 | `artifacts.json` | 法器成就/碎片/效果系数（招财铃/聚灵碗/空灵笛/轮回珠已真接入数值；结界符为联机后开启） |

### 编辑器类型
- **结构化编辑器**（gallery / music / pool / home / banner）：点选即改，带字段说明，不易写崩。
- **通用 JSON 编辑器**（pet / shrine / artifacts / bottle / farm / race / checkin）：直接编辑 JSON 文本。这里**务必注意格式**（见第 5 节），改崩会被 CI 拦下、发不上去。

## 4. 一次标准改参流程（推荐）

1. 打开 `#/admin`，进目标模块。
2. 先点「快照」存一份当前态（防改崩可秒回）。
3. 改数值 / 文案 / 加一条新物品。
4. 点「变更对比」确认只动了想动的地方。
5. 点「保存」。
6. 浏览器开 `http://localhost:5173/#/app`（玩家视角）验证效果。
7. 确认无误后，在终端：
   ```bash
   git add public/content
   git commit -m "内容更新：<模块>-<改了啥>"
   git push
   ```
8. 等 Actions 跑完（约 1 分钟），玩家刷新即见。

## 5. 改 JSON 的安全红线（避免踩坑）

CI 的 `validate-content.mjs`（D 质量防护）会拦这些，但**本地保存不拦**，所以改完最好自查：

- **别删顶层必填键**：如 `race.maxMs`、`farm.crops`、`artifacts` 各项的 `multiplier`、`bottle.emotionSet`。
- **数值要写数字，别写字符串**：`"multiplier": 1.2` ✅，`"multiplier": "1.2"` ❌（虽不会 JSON 报错，但 App 计算会出问题）。
- **别出现 `NaN` / `Infinity`**：JSON 标准不支持，CI 全树扫描会拦。
- **数组元素别漏 `id`**：作物、法器、壁纸等靠 `id` 定位，重复/缺失会在 App 侧错乱。
- **枚举值要对**：如 `pet_element` 只能用 `wood/fire/earth/metal/water`；`emotion` 取值见 `bottle.emotionSet`。
- **改完用「变更对比」**：能直观看到 diff，比肉眼找括号靠谱。

> 万一改崩且已保存：用「快照」回滚，或 `git checkout public/content/<id>.json` 放弃本地改动。

## 6. 后台鉴权（可选但建议启用）

默认后台**不设防**（任何能跑 dev 的人都能进）。上线后给后台加口令：

```bash
# 方式一：命令行临时设
ADMIN_TOKEN=你的强口令 npm run dev

# 方式二：写进 .env.local（已被 gitignore，别把真实口令提交进仓库）
# .env.local 里加一行：
# ADMIN_TOKEN=你的强口令
```

设了之后：
- 所有 `/__admin_api/*` 写接口必须带正确令牌，否则 401。
- 前端入口会弹「🔒 后台口令」框，口令存 sessionStorage，关页/刷新需重输。
- **不设 `ADMIN_TOKEN` 时完全不拦截**，向后兼容。

> 注意：这是「防外人进你本地后台乱改」的门，不是「防玩家作弊」的方案（玩家进度在客户端，详见部署指南 §8）。

---

## 7. 加一个新内容项（举例：新增一种灵田作物）

1. 进「玩法配置 → 灵田」，切 JSON 编辑器。
2. 在 `crops` 数组里复制一条现有作物，改 `id`（唯一）、`name`、`element`、`growSeconds`、`reward` 等。
3. 「变更对比」确认结构一致。
4. 保存 → 玩家视角验证。
5. `git add && commit && push`。

> 复杂嵌套新增（如新赛道皮肤）同理：先复制一条最接近的现状，再改字段，避免凭空写错结构。

---

## 8. 常见问题

- **后台打不开 / 白屏**：确认是 `npm run dev` 起的（不是 preview/build）；地址栏是 `#/admin` 而非 `/admin`。
- **保存没反应**：先看有没有红色错误提示（JSON 非法或校验不过）；若设了 `ADMIN_TOKEN` 但令牌错，会 401，重输口令。
- **改了玩家那边没变**：确认 push 了 + Actions 跑完；玩家若开着旧页，刷新即可（SW 不缓存 content，但旧页内存里还是旧值）。
- **想批量改多个模块**：逐个进模块保存，提交时 `git add public/content` 一次性提交全部。
